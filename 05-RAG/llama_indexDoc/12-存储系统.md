# 12 - StorageContext 与持久化源码分析

> 基于 `llama-index` 0.14.23。核心文件：
> `llama-index-core/llama_index/core/storage/storage_context.py`。

## 1. `StorageContext` 是容器，不是数据库

`StorageContext` 是 dataclass，聚合构建/恢复 Index 所需的存储实现：

```python
@dataclass
class StorageContext:
    docstore: BaseDocumentStore
    index_store: BaseIndexStore
    vector_stores: dict[str, BasePydanticVectorStore]
    graph_store: GraphStore
    property_graph_store: PropertyGraphStore | None = None
```

职责边界：

- `docstore`：`BaseNode` 正文、metadata、ref-doc 到 node 的映射。
- `index_store`：`IndexStruct`，即索引类型和节点/索引结构关系。
- `vector_stores`：按 namespace 保存一个或多个向量后端。
- `graph_store`：简单知识图谱。
- `property_graph_store`：可选属性图，加载时允许文件不存在。

它不包含 chat store；会话历史是 Memory/chat-store 子系统。

## 2. `from_defaults()` 的两个分支

无 `persist_dir` 时：

```python
from llama_index.core import StorageContext

storage = StorageContext.from_defaults()
```

源码会创建 `SimpleDocumentStore`、`SimpleIndexStore`、`SimpleGraphStore`、
默认 `SimpleVectorStore`，还会默认创建 `image` namespace 的
`SimpleVectorStore`。因此默认 `vector_stores` 通常至少有 `default` 和 `image`。

提供 `vector_store=` 时，它被放入 `default` namespace：

```python
storage = StorageContext.from_defaults(vector_store=qdrant_store)
```

提供 `persist_dir` 时，各 simple store 由目录加载；若没有显式外部
`vector_store/vector_stores`，则调用
`SimpleVectorStore.from_namespaced_persist_dir()` 扫描所有命名空间文件。
这里的 `persist_dir` 是“加载现有状态”，目录或必要文件错误会在构造时暴露。

参数优先级值得注意：

- `vector_store` 非空时覆盖成 `{default: vector_store}`；
- 否则使用显式 `vector_stores`；
- 否则创建默认 store 或从目录扫描；
- 显式 `image_store` 最后写入 `image`，可覆盖同名 namespace。

## 3. VectorStore namespace

定义在 `vector_stores/simple.py`：

```python
DEFAULT_VECTOR_STORE = "default"
NAMESPACE_SEP = "__"
```

添加 namespace：

```python
storage.add_vector_store(text_store, namespace="tenant_a")
storage.add_vector_store(image_store, namespace="image")
default_store = storage.vector_store  # 兼容属性，等于 vector_stores["default"]
```

持久化文件规则是：

```text
{namespace}__{vector_store_fname}
```

默认形成 `default__vector_store.json`、`image__vector_store.json`。namespace 是文件名
协议的一部分，避免使用 `__`、路径分隔符或不可信用户输入。

## 4. `persist()` 的精确调用链

```python
index.storage_context.persist(persist_dir="./storage")
```

`StorageContext.persist()` 顺序调用：

1. `docstore.persist(.../docstore.json)`
2. `index_store.persist(.../index_store.json)`
3. `graph_store.persist(.../graph_store.json)`
4. 若存在，`property_graph_store.persist(.../property_graph_store.json)`
5. 遍历 `vector_stores`，分别写 `{namespace}__vector_store.json`

这些默认文件名分别定义在各 store 的 `types.py`/simple 实现中，不应从
`core/constants.py` 的序列化 key 推断。`constants.py` 中的 `DOC_STORE_KEY` 等用于
`to_dict()/from_dict()`，不是文件名。

`persist()` 是同步方法，没有跨多个 store 的事务：中途失败会留下部分新、部分旧的
状态。生产更新应写临时版本目录，全部成功后再原子切换指针/目录。

## 5. fsspec 远程文件系统

仅写 `"s3://..."` 字符串而不传 `fs` 并不会自动按 S3 处理；源码在 `fs is None` 时
使用本地 `pathlib.Path`。正确模式是显式提供 fsspec filesystem：

```python
import fsspec

fs = fsspec.filesystem("s3")
storage.persist("bucket/prefix/storage", fs=fs)

loaded = StorageContext.from_defaults(
    persist_dir="bucket/prefix/storage",
    fs=fs,
)
```

远程分支通过 `concat_dirs()` 拼接，注释明确不支持 Windows 路径语义。后端一致性、
凭证和并发覆盖由具体 fsspec 实现负责。

## 6. 恢复 Index 的调用链

```python
from llama_index.core import StorageContext, load_index_from_storage

storage = StorageContext.from_defaults(persist_dir="./storage")
index = load_index_from_storage(storage, index_id="customer-kb")
```

`indices/loading.py::load_index_from_storage()` 实际执行：

```text
load_index_from_storage()
  -> load_indices_from_storage()
  -> index_store.get_index_struct(index_id)
     或 index_store.index_structs()
  -> index_struct.get_type()
  -> INDEX_STRUCT_TYPE_TO_INDEX_CLASS[type_]
  -> index_cls(index_struct=..., storage_context=..., **kwargs)
```

不传 `index_id` 时会加载全部 index struct，但单索引入口要求结果恰好一个：0 个或多于
1 个都抛 `ValueError`。多个索引应调用 `load_indices_from_storage()` 或显式指定 ID。
恢复过程不会重新 embedding；它依赖向量后端、embedding 配置与保存时兼容。

## 7. `to_dict()/from_dict()` 的限制

```python
snapshot = storage.to_dict()
storage2 = StorageContext.from_dict(snapshot)
```

只有 doc/index/vector/graph 全部是 simple 实现，且 property graph 是 simple 或空时
可用；只要存在 Qdrant 等外部 store 就会抛 `ValueError`。这是内存 simple storage 的
序列化，不是任意插件的通用备份格式。

## 8. 外部向量库的语义

外部 `BasePydanticVectorStore.persist()` 可能是 no-op，因为数据已经由服务端持久化。
`StorageContext.persist()` 不能替代 Qdrant/Postgres 的备份。

连接已有 collection：

```python
from llama_index.core import VectorStoreIndex

storage = StorageContext.from_defaults(vector_store=qdrant_store)
index = VectorStoreIndex.from_vector_store(
    vector_store=qdrant_store,
    storage_context=storage,
    embed_model=embed_model,
)
```

这要求 store 的 `stores_text` 等能力满足构造条件。查询 embedding 模型必须与已有向量
一致。若业务依赖 ref-doc 删除、文档更新或自定义 IndexStruct，还需确认 docstore 和
index_store 是否已恢复，不能假设 collection 单独包含全部 LlamaIndex 状态。

## 9. DocStore 与 IndexStore

```python
storage.docstore.add_documents(nodes)
node = storage.docstore.get_document(node_id)
ref_info = storage.docstore.get_ref_doc_info(ref_doc_id)

storage.index_store.add_index_struct(index_struct)
saved = storage.index_store.get_index_struct(index_id)
```

DocStore 的 `allow_update`、`store_text` 会影响重复写入和正文保存。IndexStore 保存的是
结构，不保存向量本身。`index.delete_ref_doc(..., delete_from_docstore=True)` 通常需要
协调 index struct、vector store 和 docstore，后端删除能力不完整时可能残留数据。

## 10. 常见陷阱

- 不要把 `StorageContext` 与 chat-store 混为一谈。
- 默认会有 `image` namespace；不要只按“一个 vector store”理解文件数。
- `persist()` 无事务、无进程锁，同一目录并发写可能损坏快照。
- `fs` 必须在保存和加载两侧一致传入。
- 外部 store 的数据生命周期与本地 `index_store.json` 不一致时，恢复可能成功但查询
  结果错误。
- 多 Index 快照不传 `index_id` 会报“Expected to load a single index”。
- `to_dict()` 仅支持全 simple store。
