# 15 - 评估框架：检索指标与生成质量

> 版本范围：`llama-index-core 0.14.23`。本文只描述本地源码，不把托管评估平台或历史 API 混入核心框架。

## 1. 两条评估链路

LlamaIndex 的评估不是一个统一“总分”，而是两套输入、输出都不同的机制：

1. **检索评估**：给定 `query + expected_ids`，实际调用 Retriever，比较返回节点 ID 的排序；入口是 `BaseRetrievalEvaluator`。
2. **生成评估**：给定 `query + contexts + response`，由规则、Embedding 或另一个 LLM 判分；入口是 `BaseEvaluator`。

典型离线闭环：

```text
标注集
  ├─ query + expected node ids ──> RetrieverEvaluator ──> HitRate/MRR/...
  └─ query + reference/context ──> QueryEngine ──> Response
                                      └───────────────> BaseEvaluator 子类
```

## 2. 生成评估抽象

源码：

- `llama-index-core/llama_index/core/evaluation/base.py`
- `llama-index-core/llama_index/core/evaluation/batch_runner.py`
- `llama-index-core/llama_index/core/evaluation/__init__.py`

`EvaluationResult` 是统一结果模型，字段包括：

- 输入快照：`query`、`contexts`、`response`
- 结论：`passing: Optional[bool]`、`score: Optional[float]`
- 可解释信息：`feedback`
- Pairwise 来源：`pairwise_source`
- 解析失败：`invalid_result`、`invalid_reason`

`BaseEvaluator` 以异步方法为真正扩展点：

```text
evaluate(...)
  -> asyncio_run(aevaluate(...))

evaluate_response(query, Response)
  -> response.response
  -> [source_node.get_content() for source_node in response.source_nodes]
  -> evaluate(query, response_str, contexts)
```

因此自定义 evaluator 应实现 `aevaluate()`；同步入口只是桥接。`evaluate_response()` 会自动从 `Response.source_nodes` 取上下文，但这不代表“引用一定正确”，它只负责搬运数据。

## 3. 生成质量 Evaluator

| 类 | 主要输入 | 判分机制 | 源码 |
|---|---|---|---|
| `FaithfulnessEvaluator` | response, contexts | LLM 判断答案是否被任一上下文支持 | `evaluation/faithfulness.py` |
| `RelevancyEvaluator` | query, response, contexts | LLM 判断答案/上下文对问题是否相关 | `evaluation/relevancy.py` |
| `AnswerRelevancyEvaluator` | query, response | LLM 打分回答相关性 | `evaluation/answer_relevancy.py` |
| `ContextRelevancyEvaluator` | query, contexts | LLM 打分检索上下文相关性 | `evaluation/context_relevancy.py` |
| `CorrectnessEvaluator` | query, response, reference | LLM 对参考答案打分 | `evaluation/correctness.py` |
| `SemanticSimilarityEvaluator` | response, reference | Embedding 余弦相似度与阈值 | `evaluation/semantic_similarity.py` |
| `PairwiseComparisonEvaluator` | response, second_response | LLM 成对比较，可翻转顺序缓解位置偏差 | `evaluation/pairwise.py` |
| `GuidelineEvaluator` | query/response/contexts | 按自然语言 guideline 判断 | `evaluation/guideline.py` |

### 3.1 Faithfulness 的真实调用流

`FaithfulnessEvaluator.aevaluate()` 并非逐句做 NLI，而是临时创建摘要索引：

```text
contexts
  -> 每段包装为 Document
  -> SummaryIndex.from_documents(docs)
  -> index.as_query_engine(
       llm=judge_llm,
       text_qa_template=eval_template,
       refine_template=refine_template)
  -> query_engine.aquery(response)
  -> 输出含 "yes" => passing=True, score=1.0
```

源码：`llama-index-core/llama_index/core/evaluation/faithfulness.py:159-201`。

注意：

- 默认提示词只要求 `YES/NO`，最终实现是字符串包含判断，不是结构化解析。
- `query` 被写入结果，但核心判断实际使用的是 `response + contexts`。
- `raise_error=True` 时不忠实会抛异常，否则返回失败结果。
- Judge LLM 默认取 `Settings.llm`，生产评测应显式传入稳定模型并固定提示词。

### 3.2 Correctness 与参考答案

`CorrectnessEvaluator` 面向“回答是否正确”，需要通过 `reference` 额外参数提供参考答案；不要把 faithfulness 当 correctness：

- 忠实但答非所问：faithfulness 可能高，relevancy/correctness 低。
- 与参考答案接近但上下文不支持：correctness 可能高，faithfulness 低。

### 3.3 SemanticSimilarity

`SemanticSimilarityEvaluator` 使用 `BaseEmbedding` 比较 `response` 与 `reference`，适合低成本回归；它衡量语义接近，不保证事实正确，也不能识别上下文外幻觉。

## 4. 检索评估框架

源码：

- `evaluation/retrieval/metrics_base.py`
- `evaluation/retrieval/metrics.py`
- `evaluation/retrieval/base.py`
- `evaluation/retrieval/evaluator.py`

核心对象：

```text
BaseRetrievalMetric.compute(...)
  -> RetrievalMetricResult(score, metadata)

BaseRetrievalEvaluator.aevaluate(query, expected_ids, expected_texts, mode)
  -> _aget_retrieved_ids_and_texts(...)
  -> 对每个 metric.compute(...)
  -> RetrievalEvalResult
```

`RetrieverEvaluator._aget_retrieved_ids_and_texts()`：

1. `await retriever.aretrieve(query)`；
2. 依次同步调用可选的 `node_postprocessor.postprocess_nodes()`；
3. 返回 `node.node.node_id` 与 `node.text`。

这意味着评测 ID 必须与 Retriever 最终返回的 **Node ID** 对齐，而不是文件名、`ref_doc_id` 或向量数据库内部主键。

创建方式：

```python
from llama_index.core.evaluation import RetrieverEvaluator

evaluator = RetrieverEvaluator.from_metric_names(
    ["hit_rate", "mrr", "precision", "recall", "ap", "ndcg"],
    retriever=index.as_retriever(similarity_top_k=5),
)
result = evaluator.evaluate(
    query="退款期限是多久？",
    expected_ids=["node-policy-refund"],
)
print(result.metric_vals_dict)
```

## 5. 内置检索指标的精确定义

注册表 `METRIC_REGISTRY` 位于 `evaluation/retrieval/metrics.py:496-504`。

| 名称 | 类 | 0.14.23 实现 |
|---|---|---|
| `hit_rate` | `HitRate` | 默认只要任一命中就是 1，否则 0 |
| `mrr` | `MRR` | 第一个相关结果排名 `r` 的 `1/r` |
| `precision` | `Precision` | `|set(retrieved) ∩ set(expected)| / |set(retrieved)|` |
| `recall` | `Recall` | `|set(retrieved) ∩ set(expected)| / |set(expected)|` |
| `ap` | `AveragePrecision` | 每个相关位置的 Precision 累加，再除以 expected 去重数 |
| `ndcg` | `NDCG` | 二元相关性的 DCG/IDCG，位置上限是实际结果数 |
| `cohere_rerank_relevancy` | `CohereRerankRelevancyMetric` | Cohere rerank 分数按 max/mean/median 聚合 |

重要边界：

- 前六个 ID 指标在空 `retrieved_ids` 或空 `expected_ids` 时抛 `ValueError`，不是返回 0。
- `Precision`/`Recall` 用集合，重复 ID 不重复计数。
- 默认 `HitRate` 不是“命中比例”；`use_granular_hit_rate=True` 才按命中数除以 expected 数。
- 默认 `MRR` 只看第一个相关项；`use_granular_mrr=True` 是本项目自定义的相关项倒数排名均值。
- `NDCG` 只支持二元相关，因为 `expected_ids` 没有等级标签。
- 名字虽叫 MRR，但单条 query 的结果是 reciprocal rank；数据集均值需要调用方再聚合。

## 6. 多模态检索评估

`MultiModalRetrieverEvaluator` 仍调用同一个 retriever，但按 `mode` 过滤：

- `RetrievalEvalMode.TEXT`：收集 `TextNode`
- `RetrievalEvalMode.IMAGE`：收集 `ImageNode`

`ImageNode` 继承 `TextNode`，源码中两个 `if` 都会执行，所以 ImageNode 同时进入 image 与 text 列表。这是 0.14.23 的实际行为；评测 image/text 分桶时应针对自己的数据验证，不要假定二者严格互斥。

## 7. 批量评估

`BatchEvalRunner` 接收 `{name: evaluator}`，提供：

- `aevaluate_response_strs()`：已有字符串答案/上下文；
- `aevaluate_responses()`：已有 `Response`；
- `aevaluate_queries()`：先并发调用 `query_engine.aquery()`，再评估；
- 对应三个同步包装方法。

执行机制：

```text
queries × evaluators
  -> worker coroutine
  -> asyncio.Semaphore(workers)
  -> tenacity: 最多 3 次，指数等待 4~10 秒
  -> gather
  -> Dict[evaluator_name, List[EvaluationResult]]
```

`eval_kwargs_lists` 可按 evaluator 分别提供 reference 等参数。输入列表长度必须一致；`None` 会扩为等长列表。

## 8. 推荐评估矩阵

一个 RAG 回归集至少分开报告：

1. **检索覆盖**：Recall@K、HitRate@K。
2. **排序质量**：MRR、NDCG、AP。
3. **上下文质量**：ContextRelevancy。
4. **答案对题**：AnswerRelevancy/Relevancy。
5. **有据可依**：Faithfulness。
6. **有标准答案时**：Correctness + SemanticSimilarity。
7. **版本对比时**：Pairwise，并启用顺序翻转能力。

不要将 Judge LLM 的 `score` 与 ID 指标混成一个无解释的总分。应固定数据集、Node ID 生成策略、`top_k`、后处理器、Judge 模型和提示词，并分别记录均值、分位数与失败样本。
