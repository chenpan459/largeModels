# 11 - Integrations 插件体系源码分析

> 基于 `llama-index` 0.14.23 monorepo。集成源码位于
> `llama-index-integrations/`，核心抽象位于
> `llama-index-core/llama_index/core/`。

## 1. 为什么 core 与 integration 分开

`llama-index-core` 提供稳定协议和编排：`LLM`、`BaseEmbedding`、
`BasePydanticVectorStore`、`BaseReader`、`BaseRetriever`、
`BaseNodePostprocessor`、Tool 与 Storage 接口。具体厂商 SDK、鉴权和传输逻辑放在独立
发行包中，避免 core 强制安装数百种可选依赖。

仓库当前在 `llama-index-integrations/` 下约有 **620 个带
`pyproject.toml` 的独立项目**；这是 0.14.23 checkout 的近似量级，不是稳定 API
承诺，随集成增删会变化。主要类别包括：

- `llms/`、`multi_modal_llms/`、`embeddings/`
- `vector_stores/`、`graph_stores/`、`storage/`
- `readers/`、`node_parser/`、`extractors/`
- `retrievers/`、`postprocessor/`、`response_synthesizers/`
- `tools/`、`agent/`、`program/`、`callbacks/`
- `packs/`、`indices/`、`voice_agents/` 等

不要用“集成总数”判断成熟度；应检查目标包的版本、测试、依赖范围和具体类实现。

## 2. PyPI 包名与 Python namespace

以 OpenAI-like LLM 为例：

```text
llama-index-integrations/
└── llms/llama-index-llms-openai-like/
    ├── pyproject.toml
    └── llama_index/llms/openai_like/
        ├── __init__.py
        └── base.py
```

- 发行名：`llama-index-llms-openai-like`
- 导入名：`llama_index.llms.openai_like`
- 公共类：`OpenAILike`

多个 wheel 共同向 `llama_index` namespace 安装不同子包。这是 namespace-package
插件布局，不意味着安装 `llama-index-core` 后就能导入任意
`llama_index.llms.*`。出现 `ModuleNotFoundError` 时先确认对应发行包，而不是在 core
中寻找模块。

各包自己的 `pyproject.toml` 锁定兼容范围。例如此 checkout 中
`llama-index-llms-openai-like` 版本是 `0.7.2`，依赖
`llama-index-core>=0.14.3,<0.15` 和 `llama-index-llms-openai>=0.7,<0.8`。应用应锁
整组依赖，不要仅锁元包。

## 3. 安装模型

```bash
# 方便起步的元包，会带默认集成
pip install llama-index

# 精简部署：core + 明确需要的插件
pip install llama-index-core
pip install llama-index-llms-openai-like
pip install llama-index-embeddings-openai-like
pip install llama-index-vector-stores-qdrant
```

monorepo 调试某插件可对具体目录做 editable install；不要把整个
`llama-index-integrations` 当成一个 Python 包。

## 4. LLM 集成的调用边界

`OpenAILike` 源码：
`llama-index-integrations/llms/llama-index-llms-openai-like/llama_index/llms/openai_like/base.py`。
它继承 `llama_index.llms.openai.OpenAI`，复用 OpenAI 客户端、重试、同步/异步和
流式逻辑，并显式提供第三方服务的能力元数据：

```python
from llama_index.llms.openai_like import OpenAILike

llm = OpenAILike(
    model="local-model",
    api_base="http://127.0.0.1:8080/v1",
    api_key="local-placeholder",
    is_chat_model=True,
    is_function_calling_model=False,
    context_window=8192,
    max_tokens=768,
    timeout=120.0,
)
```

关键调用分支：

- `is_chat_model=True`：`chat()/achat()` 走 OpenAI chat-completions 路径。
- `False`：先用 `messages_to_prompt()` 拼文本，再走 completion，并把结果转换回
  `ChatResponse`。
- `stream_chat()/astream_chat()` 同理做流转换。
- `metadata` 报告 `context_window`、`max_tokens`、模型名和 function-calling 能力，
  上层 Memory、Agent 会据此决策。
- `tokenizer=None` 会禁用 max_tokens 的自动推断；字符串 tokenizer 名需要安装
  `[transformers]` extra。

`is_function_calling_model` 只是能力声明，不会让不支持 tools 的服务突然支持工具调用。
错误设置为 `True` 会让 `AgentWorkflow.from_tools_or_functions()` 选择
`FunctionAgent`，然后在协议层失败。

## 5. Embedding 集成

`OpenAILikeEmbedding` 源码：
`embeddings/llama-index-embeddings-openai-like/llama_index/embeddings/openai_like/base.py`。
它继承 `OpenAIEmbedding`：

```python
from llama_index.embeddings.openai_like import OpenAILikeEmbedding

embed_model = OpenAILikeEmbedding(
    model_name="bge-m3",
    api_base="http://127.0.0.1:8081/v1",
    api_key="local-placeholder",
    embed_batch_size=8,
    timeout=120.0,
)
```

构造参数是 `model_name`，传 `model=` 会被源码主动拒绝。`dimensions` 必须与服务实际
输出、向量库 collection schema 一致。索引写入与查询必须使用同一 embedding 模型和
同一归一化约定，否则不会有类型错误，却会显著损害召回。

## 6. VectorStore 集成

```python
from llama_index.core import StorageContext, VectorStoreIndex
from llama_index.vector_stores.qdrant import QdrantVectorStore

vector_store = QdrantVectorStore(client=client, collection_name="kb")
storage = StorageContext.from_defaults(vector_store=vector_store)
index = VectorStoreIndex.from_documents(documents, storage_context=storage)
```

上层依赖 `BasePydanticVectorStore` 的 `add/delete/query` 等协议，但过滤表达式、
hybrid search、稀疏向量和 metadata 能力由各后端决定，并非完全可互换。通用过滤类型
的正确导入是：

```python
from llama_index.core.vector_stores.types import (
    FilterCondition,
    FilterOperator,
    MetadataFilter,
    MetadataFilters,
    VectorStoreQuery,
)
```

`MetadataFilter`/`MetadataFilters` 不在 `llama_index.core.schema`；旧示例常在此处失效。

## 7. Reader、reranker 与工具

```python
from llama_index.core import SimpleDirectoryReader
from llama_index.readers.file import PDFReader
from llama_index.postprocessor.cohere_rerank import CohereRerank
from llama_index.tools.tavily_research import TavilyToolSpec
```

`SimpleDirectoryReader` 本身在 core，但扩展文件格式可能延迟导入独立 reader；能构造
reader 不代表系统依赖（OCR、浏览器、数据库驱动）已齐全。Postprocessor 在 retriever
之后、response synthesizer 之前运行；网络 reranker 的异步实现和批量限制应单独检查。

## 8. 自定义插件的最小原则

1. 继承 core 中最窄的抽象。
2. 同时实现所需同步/异步方法；不要在 async 方法中直接跑阻塞 SDK。
3. 正确返回 metadata，尤其 LLM context window、chat/function-calling 能力及向量维数。
4. 在 `__init__.py` re-export 公共类，保持稳定导入路径。
5. 单独声明厂商 SDK 版本和 optional extras。
6. 用真实协议响应测试流式 delta、重试、错误映射和序列化。

## 9. 常见陷阱

- PyPI 名用连字符，Python import 用下划线与 namespace 层级，二者不可互换。
- `pip install llama-index-core` 不会安装 `llama_index.llms.openai_like`。
- `OpenAILike` 不只是改 URL；正确的能力 flags 会改变上层调用链。
- OpenAI-compatible 服务通常只实现协议子集，tools、JSON schema、usage 和流式字段需
  实测。
- 外部 VectorStore 往往自行持久化；`StorageContext.persist()` 不一定能导出远端数据。
- 同一 namespace 下安装不兼容版本的插件可能导入成功但运行失败，应检查每个
  `pyproject.toml` 的 core 版本范围。
