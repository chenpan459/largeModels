# 07 — 模型模块源码分析

> 对应源码版本：LLaMA Factory `0.9.6.dev0`，默认 v0 模型栈 `src/llamafactory/model/`。

## 1. 模块边界与调用顺序

训练、导出和 Hugging Face 推理共用两个入口：

```text
load_tokenizer(model_args)
  → TokenizerModule {"tokenizer", "processor"}

load_model(tokenizer, model_args, finetuning_args,
           is_trainable=False, add_valuehead=False)
  → config patch
  → 架构选择与权重加载
  → model patch
  → adapter
  → optional value head
  → train/eval 状态与参数统计
```

模板必须在二者之间初始化：

```text
load_tokenizer()
→ get_template_and_fix_tokenizer()
→ load_model()
```

因为模板可能补 EOS/PAD/stop tokens，`load_model()` 中的 `patch_model()` 才能依据 `resize_vocab` 正确扩 embedding。

## 2. `_get_init_kwargs()` 与 Hub 下载

所有 config/tokenizer/model 加载先经过 `_get_init_kwargs()`：

1. `skip_check_imports()`；
2. `try_download_model_from_other_hub(model_args)`，可能原地替换 `model_name_or_path`；
3. 返回 `trust_remote_code/cache_dir/revision/token`。

ModelScope/OpenMind 并不是另一套模型构造流程；下载路径被规范化后仍进入 Transformers AutoClass。

## 3. `load_tokenizer()` 的精确返回

`AutoTokenizer.from_pretrained()` 首次使用 `use_fast_tokenizer`、`split_special_tokens` 和右 padding；发生 `ValueError` 时反转 fast/slow 再试。其他异常包装为 `OSError("Failed to load tokenizer.")`。

`patch_tokenizer()` 不负责设置 PAD/EOS；它修复 `_pad` 实现、放宽 `model_max_length`、添加 `add_tokens/add_special_tokens`，并在词表变化时自动把 `resize_vocab=True`。PAD/EOS 是后续 Template 的 `fix_special_tokens()` 修复。

然后尝试 `AutoProcessor.from_pretrained()`。失败只记录日志并返回 `None`；若加载对象的类名不含 `"Processor"` 也会丢弃。`patch_processor()` 把统一 tokenizer 以及图像像素、视频 FPS/长度、音频采样率等参数写回 processor。

精确返回键始终为：

```text
{"tokenizer": PreTrainedTokenizer, "processor": ProcessorMixin | None}
```

## 4. `load_model()` 主链

### 4.1 config 与加载参数补丁

`load_config()` 调用 `AutoConfig.from_pretrained()`。随后：

```text
patch_config(config, tokenizer, model_args, init_kwargs, is_trainable)
apply_liger_kernel(config, model_args, is_trainable,
                   require_logits=stage not in ["pt", "sft"])
```

`patch_config()` 的核心次序为：

1. 推导 `compute_dtype`；
2. 配置 attention implementation；
3. 配置 RoPE scaling、LongLoRA；
4. `configure_quantization()`；
5. MoE、视觉模型、KV cache；
6. 应用模型族兼容设置；
7. 根据 ZeRO-3/FSDP 控制 `low_cpu_mem_usage/device_map/offload_folder`。

ZeRO-3/FSDP 下不设置普通 device map。`device_map="auto"` 仅在 low-memory 加载路径补 offload folder。

### 4.2 模型类选择

Unsloth 优先截获可训练模型或已有 PEFT adapter。否则设置：

```text
config
pretrained_model_name_or_path
torch_dtype = "auto"
```

AutoClass 的选择顺序：

1. config 属于 `AutoModelForImageTextToText` mapping；
2. 属于 `AutoModelForSeq2SeqLM` mapping；
3. 属于 `AutoModelForTextToWaveform` mapping；
4. 否则 `AutoModelForCausalLM`。

`train_from_scratch=True` 用 `from_config()`，否则 `from_pretrained()`。Qwen2.5/3 Omni 加载后只取 `.thinker`。Mixture-of-Depths 还可选择专用 load 或 convert 路径。

### 4.3 模型补丁与 adapter

权重加载后依次：

```text
patch_model(...)
register_autoclass(config, model, tokenizer)
init_adapter(...)
```

`patch_model()` 会：

- 修正 generation config 中采样参数与 `do_sample` 的矛盾；
- 必要时绑定 Transformers `GenerationMixin.generate`；
- `add_valuehead=True` 时先调整底层模型的 lm head；
- `resize_vocab=True` 时扩 input/output embedding；
- 训练模式下启用 gradient checkpointing、projector dtype、ZeRO-3 leaf module 和模型族 forward patch；
- 输出 attention 实现并添加 `llama-factory` model tag。

## 5. Adapter 与微调模式

`init_adapter()` 支持精确四类值：

- `full`；
- `freeze`；
- `lora`；
- `oft`。

### Full

默认参数保持可训练，仅冻结视觉等 `forbidden_modules`。需要时把可训练参数升为 fp32。

### Freeze

读取文本 config 的层数：

- 正 `freeze_trainable_layers`：最后 N 层；
- 负数：最前 N 层；
- `use_llama_pro=True`：按固定 stride 均匀选择层。

`freeze_trainable_modules` 选择层内模块，`freeze_extra_modules` 选择非 hidden 模块。复合多模态模型在未冻结 projector 时会额外训练 projector。

### LoRA/OFT 的加载、合并与恢复

已有 `adapter_name_or_path` 时：

- 普通可合并场景可以顺序 `PeftModel.from_pretrained()` + `merge_and_unload()` 合并多个 adapter；
- 量化、ZeRO-3、KTransformers、Unsloth 只允许单 adapter，且不合并；
- 继续训练且 `create_new_adapter=False` 时，前面的 adapter 合并，最后一个作为可训练 adapter 恢复；
- 推理或创建新 adapter 时，所有可合并 adapter 都并入基座。

创建新 LoRA：

1. `lora_target=["all"]` 时 `find_all_linear_modules()`；
2. LLaMA Pro 可限制为扩展层；
3. `patch_target_modules()` 排除/调整视觉模块；
4. 创建 `LoraConfig(r, lora_alpha, lora_dropout, use_rslora, use_dora, modules_to_save)`；
5. 可选 PiSSA 初始化；
6. `get_peft_model()` 注入。

扩词表且未设置 `additional_target` 时，input/output embedding 自动加入 `modules_to_save`。OFT 复用同一函数，但构造 `OFTConfig(r, oft_block_size, module_dropout, ...)`。

### 参数 dtype

训练参数通常升为 fp32；例外是：

- `pure_bf16`；
- BAdam；
- 未量化的 DeepSpeed ZeRO-3（其参数已是 fp32）。

量化模型训练只允许 LoRA/OFT，且量化模型不能初始化 PiSSA。DoRA 只兼容未量化或 bitsandbytes，不兼容其他 PTQ。

## 6. 量化优先级与约束

`configure_quantization()` 明确采用：

```text
模型 config 自带 PTQ
  > export_quantization_bit（GPTQModel 导出量化）
  > quantization_bit（运行时量化）
```

### 已量化模型

识别 config 的 `quantization_config.quant_method`。GPTQ 要求 `gptqmodel>=2` 并禁用 ExLlama；AWQ、AQLM检查对应依赖。除 MXFP4/FP8 的解量化路径外，PTQ 模型与 ZeRO-3/FSDP 不兼容。

### 导出 GPTQ

`export_quantization_bit` 接受 2/3/4/8 bit，读取校准数据的 `text` 列，构造 `GPTQConfig`，强制 device map auto 与 fp16。ChatGLM 暂不支持。

### 运行时量化

- `bnb`：仅 4/8 bit；4 bit 配置 compute dtype、double quant、quant type、quant storage；
- `hqq`：1/2/3/4/5/6/8 bit，不兼容 ZeRO-3/FSDP；
- `eetq`：仅 8 bit，不兼容 ZeRO-3/FSDP。

源码枚举还包含 GPTQ、AWQ、AQLM、Quanto、MXFP4、FP8，但它们并非都能通过 `quantization_method` 做 on-the-fly 量化；部分仅用于识别模型自带 PTQ。

FSDP + QLoRA 或 `quantization_device_map="auto"` 只允许 BNB 4-bit，且要求较新 bitsandbytes。

## 7. Value head

`add_valuehead=True` 用于 RM/PPO/score 推理。调用顺序：

1. `patch_model(..., add_valuehead=True)` 的 `prepare_valuehead_model()` 统一底层 lm head；
2. adapter 初始化；
3. `AutoModelForCausalLMWithValueHead.from_pretrained(model)` 包装；
4. `patch_valuehead_model()` 补 `tie_weights`、embedding getter、RoPE getter、模型卡方法与保存忽略键；
5. 从最后一个 adapter 或基座路径加载 value-head 参数。

`load_valuehead_params()` 先查 `value_head.safetensors`，再查 `value_head.bin`，期望键：

```text
v_head.summary.weight
v_head.summary.bias
```

找不到时返回 `None`，允许新建随机 value head。RM/PPO 保存时必须由训练模块的 `fix_valuehead_checkpoint()` 拆分 wrapper 权重。

## 8. 训练态与推理态

`load_model()` 末尾：

- 推理：`requires_grad_(False)` + `eval()`；
- 训练：`train()`；
- 可选把 v1 kernel plugin 临时应用到 v0；
- 统计 trainable/all params；
- `print_param_status=True` 且 `LOCAL_RANK=0` 时逐参数打印 dtype、device、trainable。

模型 dtype 不等同于计算 dtype。加载参数使用 `torch_dtype="auto"`，量化、autocast、可训练参数 fp32 和 projector cast 会在不同层分别控制。

## 9. 导出链路

`train/tuner.py::export_model()` 仍调用 tokenizer → template → model。它不直接调用 `merge_and_unload()`；adapter 合并发生在 `init_adapter()` 的推理加载路径。

导出前约束：

- 必须指定 `export_dir`；
- adapter 与 `export_quantization_bit` 不能同时配置，必须先合并再量化；
- 已量化模型不能再合并 adapter；
- 结果必须是 `PreTrainedModel`。

非量化模型按 `infer_dtype` 转 dtype 后 `save_pretrained()`；量化模型 config dtype 设为 fp16。Transformers 5 移除了 `safe_serialization` 参数，因此源码按版本条件传递。RM 额外复制 value-head 文件，最后保存 tokenizer、processor 和自动生成的 Ollama Modelfile。

## 10. 扩展点

- 新架构：优先使用 Transformers AutoClass；必要时在 `patcher.py` 增加最小模型族补丁。
- 新 attention/RoPE/MoE：扩展 `model_utils/attention.py`、`rope.py`、`moe.py`，由 `patch_config()` 编排。
- 新参数高效方法：在 `init_adapter()` 增加类型，并处理已有 checkpoint、量化、dtype、导出。
- 新多模态模型：除 model patch 外，还要同步 data template、mm plugin、processor/collator。
- 新量化方式：明确它属于模型自带 PTQ、导出量化还是运行时量化，避免破坏优先级。

## 11. 常见陷阱

1. `patch_tokenizer()` 不保证 PAD/EOS；跳过 Template 初始化会让模型词表、停止条件和 embedding resize 不一致。
2. 多 adapter 不是“同时激活多个 LoRA”：普通路径会顺序合并，最后一个才可能作为恢复训练 adapter。
3. 量化 checkpoint、运行时 QLoRA、导出 GPTQ 是三条不同路径。
4. `add_valuehead=True` 在 adapter 注入之后包装 TRL model；调试参数名时要考虑 `pretrained_model.*` 前缀。
5. LoRA reference model 返回 `None` 可能是预期优化，不代表加载失败。
6. 量化模型不能做 full/freeze tuning，PTQ 通常也不能配 ZeRO-3/FSDP。
7. `train_from_scratch` 只随机初始化模型，tokenizer/config 仍从 `model_name_or_path` 加载。
8. processor 加载失败不会立即终止文本模型流程，但多模态 plugin 后续会因缺 processor 报错。
