# 10 — 使用指南

> 适用源码：LLaMA-Factory `0.9.6.dev0`。所有命令都假定当前目录是仓库根目录，所引用的 `examples/...` 文件均存在于该版本源码树中。参数定义与 Python/HTTP 签名见 [11-API参考](./11-API参考.md)，Board 内部机制见 [09-Web-UI与LLaMA-Board](./09-Web-UI与LLaMA-Board.md)。

## 1. 开始前检查

环境搭建细节见 [00-环境搭建指南](./00-环境搭建指南.md)。先确认版本、设备和关键依赖：

```bash
llamafactory-cli version
llamafactory-cli env
python -m json.tool data/dataset_info.json >/dev/null
```

预期版本为 `0.9.6.dev0`。训练配置中的模型会从 Hub 下载；正式训练前应确认磁盘、显存、模型访问权限和数据许可。

## 2. 最短可验证 LoRA 流程

### 2.1 检查现成配置

`examples/train_lora/qwen3_lora_sft.yaml` 使用：

- `Qwen/Qwen3-4B-Instruct-2507`
- `stage: sft`
- `finetuning_type: lora`
- `dataset: identity,alpaca_en_demo`
- `template: qwen3_nothink`
- 输出 `saves/qwen3-4b/lora/sft`

先解析 YAML 和数据注册表，避免训练启动后才发现文件错误：

```bash
python -c "import yaml; yaml.safe_load(open('examples/train_lora/qwen3_lora_sft.yaml')); print('yaml ok')"
python -c "import json; d=json.load(open('data/dataset_info.json')); assert all(x in d for x in ['identity','alpaca_en_demo']); print('datasets ok')"
```

### 2.2 小样本冒烟训练

CLI 使用 OmegaConf 合并命令行 `key=value` 覆盖项。先用独立输出目录进行短跑：

```bash
llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml \
  max_samples=16 num_train_epochs=1 \
  output_dir=saves/qwen3-4b/lora/sft-smoke \
  overwrite_output_dir=true report_to=none
```

成功标准：

1. 参数解析没有 unknown/deprecated argument；
2. 日志打印一条有效 training example；
3. loss 为有限数值；
4. 输出目录含 adapter、tokenizer/配置及 trainer 状态文件；
5. `training_loss.png` 在 `plot_loss: true` 且存在有效训练日志时生成。

确认短跑后再执行完整配置：

```bash
llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml
```

注意：现成配置包含 `overwrite_output_dir: true`，重复执行会复用并覆盖目标目录语义，不应把它当成自动断点续训。

## 3. 训练场景

### 3.1 单卡与自动多卡

```bash
# 单卡
CUDA_VISIBLE_DEVICES=0 llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml

# 检测到两张设备后，launcher 自动改用 torchrun
CUDA_VISIBLE_DEVICES=0,1 llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml
```

`launcher.py` 在设备数大于 1，且未使用 Ray/KTransformers 时自动启动分布式任务。也可用 `FORCE_TORCHRUN=1` 强制进入该分支。

### 3.2 QLoRA

当前树的 on-the-fly 4-bit 示例是 `examples/train_qlora/qwen3_lora_sft_otfq.yaml`，量化方法值为 `bnb`，不是 `bitsandbytes`：

```bash
llamafactory-cli train examples/train_qlora/qwen3_lora_sft_otfq.yaml
```

该配置设置 `quantization_bit: 4`、`quantization_method: bnb`。训练时量化只兼容 LoRA/OFT；量化模型不能 resize vocabulary，也不能一次加载多个 adapter。

### 3.3 DPO、继续预训练与全量 SFT

```bash
# 偏好优化：dpo_en_demo，pref_loss=sigmoid
llamafactory-cli train examples/train_lora/qwen3_lora_dpo.yaml

# 继续预训练：c4_demo，stage=pt
llamafactory-cli train examples/train_lora/qwen3_lora_pretrain.yaml

# 全量 SFT：配置内使用现有 examples/deepspeed/ds_z3_config.json
FORCE_TORCHRUN=1 llamafactory-cli train examples/train_full/qwen3_full_sft.yaml
```

各 stage 的数据列和内部工作流不在此重复，见 [05-训练流水线](./05-训练流水线.md) 与 [06-数据模块](./06-数据模块.md)。

### 3.4 多模态 SFT

当前 Qwen3-VL LoRA 示例为：

```bash
llamafactory-cli train examples/train_lora/qwen3vl_lora_sft.yaml
```

其准确配置是 `Qwen/Qwen3-VL-4B-Instruct`、`template: qwen3_vl_nothink`、`dataset: mllm_demo,identity,alpaca_en_demo`，并限制 `image_max_pixels` 和 `video_max_pixels`。视频数据可把 dataset 覆盖为注册表中已有的 `mllm_video_demo`：

```bash
llamafactory-cli train examples/train_lora/qwen3vl_lora_sft.yaml \
  dataset=mllm_video_demo max_samples=16 \
  output_dir=saves/qwen3-vl-4b/lora/video-smoke
```

多模态验证至少检查：

- 样本中的占位符数量与 image/video/audio 数量匹配；
- processor 成功加载且日志打印有效样本；
- `cutoff_len` 与像素上限不会造成持续 OOM；
- 推理时使用与训练一致的 `qwen3_vl_nothink` 模板。

## 4. 验证集、预测与结果检查

训练中验证可直接覆盖已有 SFT 示例：

```bash
llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml \
  val_size=0.1 eval_strategy=steps eval_steps=100 \
  per_device_eval_batch_size=1 \
  output_dir=saves/qwen3-4b/lora/sft-with-eval
```

`eval_dataset` 与 `val_size` 至少提供一个。生成式预测还必须同时设置 `do_predict=true` 和 `predict_with_generate=true`；它只支持 SFT，并与 DeepSpeed ZeRO-3、`compute_accuracy=true` 不兼容。仓库中的可执行生成预测示例为：

```bash
llamafactory-cli train examples/extras/nlg_eval/llama3_lora_predict.yaml
```

`llamafactory-cli eval` **不可用**：当前 launcher 的该分支直接抛出 `NotImplementedError` 并声明 evaluation 将被弃用。Board 的 Evaluate & Predict Tab 仍可用，因为它生成 `do_eval`/`do_predict` 参数后调用的是 `llamafactory-cli train`。

建议验证顺序：

1. 比较训练前后固定提示集，不只看训练 loss；
2. 保留独立验证集，避免用训练数据展示“效果”；
3. 检查 `all_results.json`、预测文件和日志中的样本数；
4. 对多轮、工具调用和多模态分别做边界测试；
5. 导出后再跑同一组提示，确认合并前后输出一致。

## 5. 断点续训

### 5.1 显式恢复

假设实际存在 `saves/qwen3-4b/lora/sft/checkpoint-500`：

```bash
llamafactory-cli train examples/train_lora/qwen3_lora_sft.yaml \
  resume_from_checkpoint=saves/qwen3-4b/lora/sft/checkpoint-500 \
  overwrite_output_dir=false
```

恢复前核对 checkpoint 中的 trainer state、optimizer/scheduler 状态以及 adapter/model 权重。`save_only_model: true` 不保存完整训练状态，不能用于真正续训。

### 5.2 自动恢复

未显式设置 `resume_from_checkpoint` 时，满足以下条件才会自动选择 `output_dir` 最后的 `checkpoint-*`：

- `do_train=true`；
- 目录已存在；
- `overwrite_output_dir=false`；
- 当前 stage/方法支持恢复。

RM/PPO 的 full/freeze 会禁用恢复；RM/PPO LoRA 还会提示把恢复 checkpoint 加入 `adapter_name_or_path`。因此生产任务应显式记录恢复路径，不依赖隐式推断。

Board 中选择已有 output directory 会恢复表单并由同一训练参数逻辑寻找 checkpoint，细节见 [09-Web-UI与LLaMA-Board](./09-Web-UI与LLaMA-Board.md)。

## 6. 分布式训练

### 6.1 DeepSpeed 与多节点

```bash
# 单节点 ZeRO-3；示例 YAML 已引用现有 ds_z3_config.json
FORCE_TORCHRUN=1 llamafactory-cli train examples/train_full/qwen3_full_sft.yaml

# 节点 0
FORCE_TORCHRUN=1 NNODES=2 NODE_RANK=0 \
MASTER_ADDR=192.168.1.100 MASTER_PORT=29500 \
llamafactory-cli train examples/train_full/qwen3_full_sft.yaml

# 节点 1
FORCE_TORCHRUN=1 NNODES=2 NODE_RANK=1 \
MASTER_ADDR=192.168.1.100 MASTER_PORT=29500 \
llamafactory-cli train examples/train_full/qwen3_full_sft.yaml
```

默认每节点进程数来自检测到的设备数，可用 `NPROC_PER_NODE` 覆盖。弹性训练还支持 `RDZV_ID`、`MIN_NNODES`、`MAX_NNODES`、`MAX_RESTARTS`。

多节点启动前验证所有节点：

- 源码、配置、数据和共享输出路径一致；
- `MASTER_ADDR:MASTER_PORT` 可达；
- 每个 `NODE_RANK` 唯一；
- NCCL/设备驱动与网络接口正常；
- DeepSpeed 配置路径在每个节点都存在。

## 7. 对话验证

先使用训练产物对应的现成推理配置：

```bash
llamafactory-cli chat examples/inference/qwen3_lora_sft.yaml
```

CLI 支持 `clear` 清空历史、`exit` 退出，但 `run_chat()` 只读取终端文本，不提供图片/视频/音频上传。多模态交互应使用 Board 或 HTTP API：

```bash
llamafactory-cli webui
```

在 Chat Tab 选择 Qwen3-VL、`qwen3_vl_nothink` 和对应 adapter，加载后上传媒体。纯聊天 Web 页面也可直接读取现有配置：

```bash
llamafactory-cli webchat examples/inference/qwen3vl.yaml
```

## 8. 导出与合并

### 8.1 文本 LoRA

```bash
llamafactory-cli export examples/merge_lora/qwen3_lora_sft.yaml
```

该文件真实输出到 `saves/qwen3_sft_merged`，默认每个 shard 5 GB、CPU 合并、非 legacy format。不要把旧文档中的 `exports/qwen3-4b-merged` 当成此示例的输出。

### 8.2 多模态 LoRA

```bash
llamafactory-cli export examples/merge_lora/qwen3vl_lora_sft.yaml
```

它输出到 `saves/qwen3_vl_sft_merged`，并保存 tokenizer、processor；导出器还生成 Ollama `Modelfile`。

导出约束：

- 不要在合并 adapter 时设置 `quantization_bit`；
- 量化模型上不能合并 adapter；
- GPTQ 导出应先合并，再单独量化；
- 导出后检查 config、权重 shards、tokenizer、processor（多模态）和 `Modelfile`；
- 用导出目录重新加载并复跑固定提示集。

## 9. OpenAI 风格 API

### 9.1 启动

```bash
API_HOST=0.0.0.0 API_PORT=8000 \
API_KEY=sk-local API_MODEL_NAME=qwen3-sft \
llamafactory-cli api examples/inference/qwen3_lora_sft.yaml
```

服务文档位于 `http://localhost:8000/docs`。`API_KEY` 非空时，所有三个 `/v1` 端点都要求 `Authorization: Bearer sk-local`。

vLLM 可基于当前树的基础模型推理配置启动：

```bash
API_PORT=8000 llamafactory-cli api examples/inference/qwen3.yaml \
  infer_backend=vllm vllm_enforce_eager=true
```

vLLM 不支持 BNB `quantization_bit`、RoPE scaling 或多个 adapter；GPTQ/AWQ 预量化模型不受这里的 BNB 限制。

### 9.2 文本请求

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="sk-local")
response = client.chat.completions.create(
    model="qwen3-sft",
    messages=[{"role": "user", "content": "请用一句话解释 LoRA。"}],
    temperature=0.7,
)
print(response.choices[0].message.content)
```

请求中的 `model` 会回显到响应，但服务实际加载哪个权重由启动配置决定；`API_MODEL_NAME` 只控制 `/v1/models` 返回的 ID。

### 9.3 多模态 API

先启动现有 Qwen3-VL 配置：

```bash
API_KEY=sk-local API_MODEL_NAME=qwen3-vl \
llamafactory-cli api examples/inference/qwen3vl.yaml
```

请求内容可含 `text`、`image_url`、`video_url`、`audio_url`。远程 URL 只允许 HTTP(S) 且拒绝私网/保留地址；本地文件默认只允许 `SAFE_MEDIA_PATH` 下的真实路径。生产环境建议显式禁用本地文件：

```bash
ALLOW_LOCAL_FILES=0 API_KEY=sk-local API_MODEL_NAME=qwen3-vl \
llamafactory-cli api examples/inference/qwen3vl.yaml
```

图片请求示例：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="sk-local")
response = client.chat.completions.create(
    model="qwen3-vl",
    messages=[{
        "role": "user",
        "content": [
            {"type": "image_url", "image_url": {"url": "https://example.com/image.jpg"}},
            {"type": "text", "text": "描述这张图片。"},
        ],
    }],
)
print(response.choices[0].message.content)
```

## 10. 常见失败定位

| 现象 | 优先检查 |
|---|---|
| unknown argument | 当前版本参数名；默认严格拒绝额外键，不要用 `ALLOW_EXTRA_ARGS` 掩盖拼写错误 |
| CUDA OOM | 降低 batch/长度/像素，增加梯度累积，改用 QLoRA；先做 16 样本短跑 |
| 找不到数据集 | `data/dataset_info.json` 名称、`dataset_dir` 和 stage 所需 ranking 类型 |
| 模板或输出异常 | 模型与 template 是否匹配；Qwen3 文本示例是 `qwen3_nothink`，Qwen3-VL 是 `qwen3_vl_nothink` |
| 多卡未启动 | 可见设备数、`FORCE_TORCHRUN`、Ray/KTransformers 开关和 launcher 日志 |
| 续训从头开始 | `overwrite_output_dir`、checkpoint 完整性、显式 `resume_from_checkpoint` |
| LoRA 合并失败 | adapter 路径、基础模型一致性、是否错误地同时量化 |
| API 401 | Bearer token 是否与 `API_KEY` 完全一致 |
| API 多模态 400/403 | 消息角色交替、URL 类型、SSRF 检查、本地路径是否位于 `SAFE_MEDIA_PATH` |
