# 13 — 分布式与硬件加速

本文分析 `0.9.6.dev0` 中从 CLI 重启进程到 Trainer 分片的完整路径，并区分 torchrun、DeepSpeed/FSDP、Ray、MCA、HyperParallel、KTransformers 与 NPU 支持各自所在的层。

## 1. 四层结构

LLaMA-Factory 的“分布式”不是单一开关：

| 层 | 职责 | 主要源码 |
|---|---|---|
| 进程启动 | 单进程还是 `torchrun`，节点/rank/端口 | `src/llamafactory/launcher.py` |
| 集群调度 | Ray worker 和 placement group | `train/tuner.py`、`train/trainer_utils.py` |
| 参数/状态分片 | DDP、DeepSpeed ZeRO、FSDP/FSDP2 | HF Trainer + Accelerate 配置 |
| 替代训练后端 | MCA、HyperParallel | `train/mca/`、`train/hyper_parallel/` |

KTransformers 是模型加载/算子后端，不是普通数据并行后端；NPU 是设备适配层。

## 2. torchrun 自动重启

`cli.py::main()` 选择 v0 launcher 后，`launcher.launch()` 判断：

```text
command == "train"
AND (
  FORCE_TORCHRUN=1
  OR (device_count > 1 AND not USE_RAY AND not USE_KT)
)
```

成立时，当前 CLI 进程通过 `subprocess.run()` 启动 `torchrun ... launcher.py <yaml>`。子进程执行 `launcher.py` 的 `__main__`，直接进入 `train.tuner.run_exp()`，不会再次无限重启。

### 2.1 固定规模参数

- `NNODES`：节点数，默认 1；
- `NODE_RANK`：本节点序号，默认 0；
- `NPROC_PER_NODE`：每节点进程数，默认设备数；
- `MASTER_ADDR`：默认 `127.0.0.1`；
- `MASTER_PORT`：默认动态空闲端口。

### 2.2 Elastic 参数

设置 `RDZV_ID` 后改用 c10d rendezvous：

- `MIN_NNODES/MAX_NNODES` 可形成弹性范围；
- `MAX_RESTARTS` 控制容错重启次数；
- endpoint 为 `MASTER_ADDR:MASTER_PORT`。

默认 `OPTIM_TORCH=1` 还写入：

```text
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
TORCH_NCCL_AVOID_RECORD_STREAMS=1
```

MCA 的特殊入口：`USE_MCA=1` 会在 launcher 中强制设置 `FORCE_TORCHRUN=1`。

## 3. DDP、DeepSpeed 与 FSDP

### 3.1 默认 DDP

多卡且没有 DeepSpeed/FSDP 配置时，HF Trainer/Accelerate 使用 DDP。`ddp_timeout`、`ddp_find_unused_parameters` 等仍来自 Transformers `Seq2SeqTrainingArguments`。

### 3.2 DeepSpeed

YAML 通过 `deepspeed: path/to/config.json` 交给 HF Trainer。示例：

- `examples/train_lora/qwen3_lora_sft_ds3.yaml`
- 仓库中的 DeepSpeed JSON 配置目录（由示例路径引用）

LLaMA-Factory 自己补充的逻辑：

- DPO/KTO reference model：TRL `prepare_deepspeed()`；
- PPO：把 `deepspeed_plugin` 和 DDP kwargs 传入 TRL `PPOConfig`；
- PPO 保存：优先 `accelerator.get_state_dict()`，ZeRO-3 不聚合权重时保存完整 checkpoint，并提示使用 `zero_to_fp32.py`；
- BAdam layer mode把 `is_deepspeed_zero3_enabled()` 传给 `BlockOptimizer`；
- WebUI 发现 `deepspeed` 参数时设置 `FORCE_TORCHRUN=1`。

### 3.3 FSDP/FSDP2

v0 的 FSDP 由 Accelerate/HF Trainer 配置驱动，参考：

- `examples/accelerate/fsdp_config.yaml`
- `fsdp_config_offload.yaml`
- `fsdp_config_multiple_nodes.yaml`
- `fsdp2_config.yaml`
- `fsdp2_config_qwen35.yaml`
- `fsdp2_config_qwen35_moe.yaml`

通常先设置 Accelerate 配置，再由 `llamafactory-cli train` 启动。DPO/KTO 对 reference model 区分 FSDP1 与 FSDP2：前者走 TRL `prepare_fsdp()`，后者走 `accelerate.utils.fsdp_utils.fsdp2_prepare_model()`。

Ascend 示例集中在 `examples/ascend/`，覆盖 Qwen3/Qwen3.5、VLM/MoE 与 FSDP/FSDP2。

## 4. Ray 集群训练

Ray 开关不是 YAML 的普通布尔项，而是环境变量：

```bash
USE_RAY=1 llamafactory-cli train config.yaml
```

`extras.misc.use_ray()` 读取 `USE_RAY`；`TrainingArguments` 继承 `RayArguments` 并设置 `use_ray`。调用链：

```text
run_exp()
  → get_ray_args()
  → _ray_training_function()
  → ray.init()
  → 校验集群设备数
  → get_placement_group()
  → 按节点 IP 排序 bundles
  → 每个 bundle 创建一个 ray.remote(Worker)
  → Worker._training_function()
  → 普通 _training_function()
```

参数来源 `src/llamafactory/hparams/training_args.py::RayArguments`：

- `ray_num_workers`
- `ray_init_kwargs`
- `master_addr`
- `master_port`

每个 worker 的环境由 `get_ray_remote_config_for_worker()` 写入 rank、world size、master 地址和可见设备。若 Ray 已设置设备可见性，Worker 把 `LOCAL_RANK` 置 0；若设置 `RAY_EXPERIMENTAL_NOSET_CUDA_VISIBLE_DEVICES` 或 `RAY_EXPERIMENTAL_NOSET_ASCEND_RT_VISIBLE_DEVICES`，则从 Ray accelerator id 恢复本地 rank。

Ray 负责资源调度，worker 内仍运行相同的 Trainer/DeepSpeed/FSDP 逻辑。示例：`examples/train_lora/qwen3_lora_sft_ray.yaml`。

## 5. MCA：Megatron Core Adapter

启用条件：

```bash
USE_MCA=1 llamafactory-cli train examples/megatron/qwen3_moe_full.yaml
```

`hparams/training_args.py` 在 import 时检测 `USE_MCA`，把基础参数类从 Transformers `Seq2SeqTrainingArguments` 替换为 `mcore_adapter.Seq2SeqTrainingArguments`。随后：

```text
launcher：强制 torchrun
tuner：use_mca=True 且 stage ∈ {pt,sft,dpo}
  → train/mca/workflow.py::run_pt/run_sft/run_dpo
  → mcore_adapter.models.AutoModel
  → CustomMcaTrainer 或 mcore_adapter.trainer.DPOTrainer
```

特征：

- 支持 PT、SFT、DPO，不支持 RM/PPO/KTO；
- `_check_model_support()` 对照 `extras.constants.MCA_SUPPORTED_MODELS`；
- 数据仍使用 LLaMA-Factory template/processor/collator；
- MCA 自己做 shift，workflow 临时把 `cutoff_len` 加 1，再由 `_data_collator_wrapper()` 去掉首尾；
- SFT 对 expert parallel 使用固定长度与 64 对齐；
- DPO 创建 `DPOConfig(beta, pref_loss, label_smoothing)`；
- `scripts/megatron_merge.py` 把 MCA checkpoint 转回 HF 格式。

MCA 是独立模型与 Trainer 后端，不应与普通 HF DeepSpeed/FSDP 心智模型混用。

## 6. HyperParallel

配置字段定义在 `FinetuningArguments`：

- `use_hyper_parallel`
- `hyper_parallel_args`：策略 JSON 路径；
- `hyper_parallel_cp_size`

当前路由只支持 `stage in {pt,sft}`，并要求安装 `hyper_parallel`。调用链：

```text
tuner._training_function()
  → train/hyper_parallel/workflow.py
  → _prepare_hp_args()
  → HyperParallelArguments.from_finetuning_args()
  → HyperParallelTrainer
```

限制由参数说明明确为 PT/SFT + full tuning。若 HyperParallel 开启 activation optimization，workflow 会关闭 LLaMA-Factory 原生 gradient checkpointing，让后端接管。它复用 v0 数据、模型加载和评测逻辑，但 Trainer 的 FSDP/TP/CP 组合由 HyperParallel 安装。

## 7. KTransformers（KT）

启用开关是 `USE_KT=1`；`ModelArguments` 最终得到 `use_kt`。自动 torchrun 条件会排除 KT，避免按可见设备数启动普通 DDP。

影响范围：

- Chat 路径使用 `chat/kt_engine.py`；
- 模型 loader/adapter 走 KTransformers 装载；
- 只支持 LoRA 微调；
- 只允许单一 adapter，不能像普通 PEFT 那样先合并多个 adapter；
- 模型卡增加 `kt-kernel` tag。

示例：

- `examples/ktransformers/train_lora/*_lora_sft_kt.yaml`
- `examples/ktransformers/accelerate/fsdp2_kt_*.yaml`

KT 面向 DeepSeek/Qwen MoE 的 CPU/GPU 异构与自定义 kernel；它可与专用 FSDP2 配置组合，但不是 MCA 或 HyperParallel 的替代语法。

## 8. NPU / Ascend

设备抽象集中在 `extras/misc.py`：

```text
get_current_device() → npu:$LOCAL_RANK
get_device_count()   → torch.npu.device_count()
get_torch_device()   → torch.npu
torch_gc()           → torch.npu.empty_cache()
```

主要适配点：

- parser 检查 `torch.npu.is_bf16_supported()`；
- WebUI 在 NPU 量化时关闭 bitsandbytes double quantization；
- attention 检查允许 NPU 进入兼容路径；
- callbacks 读取 NPU 峰值显存；
- `model/patcher.py` 为 Qwen3.5 Gated DeltaNet 检查 `triton_ascend`，替换 NPU 兼容 kernel；
- v1 另有 `plugins/model_plugins/kernels/ops/` 下的 `npu_rope.py`、`npu_rms_norm.py`、`npu_swiglu.py`、`npu_fused_moe.py`。

安装依赖参考 `requirements/npu.txt`、`requirements/triton_ascend.txt`（后者要求不能与普通 Triton 共存）。训练示例见 `examples/ascend/` 以及 `train_qlora/qwen3_lora_sft_bnb_npu.yaml`。

## 9. FP8 与 Liger

FP8 参数在 `hparams/training_args.py::Fp8Arguments`：

- `fp8`
- `fp8_backend=auto|torchao|te|msamp`
- `fp8_enable_fsdp_float8_all_gather`

`train/fp8_utils.py` 通过 Accelerate 配置 FP8；TorchAO 路径跳过 embedding/lm_head/classifier 和维度非 16 倍数的 Linear，TE 路径会 patch `Accelerator.__init__()` 注入 recipe。当前说明要求 PyTorch 2.7+ 与 Hopper GPU。示例分别覆盖 DeepSpeed 和 FSDP。

Liger 则由 `model/model_utils/liger_kernel.py` 注入融合 kernel，开关 `enable_liger_kernel`；它是单机/分布式都可叠加的模型算子优化，不负责进程或参数分片。

## 10. 选择矩阵

| 目标 | 首选 |
|---|---|
| 单机多卡常规训练 | 自动 torchrun + DDP |
| 降低 optimizer/参数显存 | DeepSpeed ZeRO-2/3 或 FSDP2 |
| 多节点资源编排 | Ray + 内部训练后端 |
| Megatron TP/PP/EP 生态 | MCA |
| PT/SFT 的 FSDP/TP/CP 组合 | HyperParallel |
| 巨型 MoE 异构加载 | KT |
| Ascend | torch_npu + `examples/ascend` 配置 |

## 11. 常见误区

1. `USE_RAY`、`USE_KT`、`USE_MCA` 是环境变量；`use_hyper_parallel` 是训练参数。
2. torchrun 只创建进程；是否 ZeRO/FSDP 要看训练配置。
3. Ray 并不自动把模型变成模型并行，它只是创建和放置 worker。
4. MCA 在 import 参数类时就依赖环境变量，不能在 Python 已导入后再临时切换。
5. v1 有自己的 DeepSpeed/FSDP2 plugin，不等于 v0 的 HF Trainer 集成，详见下一章。
