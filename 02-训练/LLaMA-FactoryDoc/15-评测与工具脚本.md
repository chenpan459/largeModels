# 15 — 评测与工具脚本

`0.9.6.dev0` 同时保留了旧式选择题 Evaluator、基于 SFT workflow 的 WebUI 评测，以及 `scripts/` 下的离线评估/转换/统计工具。三者入口和产物不同，不能混为一个“eval 命令”。

## 1. 三类评测

| 类型 | 入口 | 用途 | 当前状态 |
|---|---|---|---|
| legacy Evaluator | `src/llamafactory/eval/` | MMLU/CMMLU/CEval 类选择题准确率 | 源码保留，CLI 已禁用 |
| Trainer eval/predict | `stage=sft + do_eval/do_predict` | loss、token accuracy、生成指标、预测文件 | 主路径 |
| 独立脚本 | `scripts/eval_bleu_rouge.py`、`stat_utils/cal_ppl.py` 等 | 后处理和专项指标 | 手动运行 |

## 2. Legacy Evaluator

### 2.1 入口现状

`src/llamafactory/eval/evaluator.py` 仍定义：

```text
Evaluator.__init__()
Evaluator.batch_inference()
Evaluator.eval()
Evaluator._save_results()
run_eval()
```

但 `src/llamafactory/launcher.py` 的 `command == "eval"` 分支直接：

```text
raise NotImplementedError("Evaluation will be deprecated in the future.")
```

因此 `llamafactory-cli eval ...` 在当前版本不可用。若研究旧实现，可直接阅读或在 Python 中显式调用 `run_eval()`，但它不再是受支持的 CLI 流程。

### 2.2 调用链

```text
Evaluator()
  → get_eval_args()
  → load_tokenizer()
  → get_template_and_fix_tokenizer()
  → load_model()
  → get_eval_template(lang)
Evaluator.eval()
  → cached_file(task_dir/task/mapping.json)
  → load_dataset(..., name=subject)
  → 从 train split 随机抽 n_shot
  → EvalTemplate.format_example()
  → template.encode_oneturn()
  → batch_inference()
  → _save_results()
```

`eval/template.py::EvalTemplate` 只有 `en` 和 `zh` 两个提示模板。每个样本要求 `question/A/B/C/D/answer` 字段。

`batch_inference()` 不生成完整答案，而是：

1. 找每条 prompt 最后一个有效 token；
2. 取该位置 logits；
3. 只截取 A/B/C/D 对应 token id；
4. softmax 后 argmax。

结果按 `extras.constants.SUBJECTS` 汇总，`save_dir` 下写：

- `results.json`：每个 subject 的逐题预测；
- `results.log`：类别和 Average 准确率。

局限：

- 选项必须能由各自最后 token 稳定表示；
- n-shot 每道题重新 shuffle，没有显式固定局部 seed；
- 只适合选择题，不是通用生成评测；
- CLI 已明确弃用方向。

## 3. WebUI Evaluation 的真实实现

WebUI “Evaluation” 标签页不是 legacy Evaluator。入口链：

```text
webui/components/eval.py::create_eval_tab()
  → Runner._parse_eval_args()
  → Runner._launch(do_train=False)
  → Popen(["llamafactory-cli", "train", generated_yaml])
  → train/tuner.py
  → train/sft/workflow.py::run_sft()
```

`_parse_eval_args()` 固定：

```text
stage="sft"
predict_with_generate=True
report_to="none"
```

用户勾选 Predict：

- 勾选：`do_predict=True`；
- 不勾选：`do_eval=True`。

也就是说：

- **do_eval**：Trainer evaluate，通常输出 eval loss/accuracy/相似度；
- **do_predict**：调用 generate，保存生成预测并计算生成指标。

### 3.1 参数映射

UI 字段映射到：

- 模型/template/adapter/quantization；
- `eval_dataset`、`dataset_dir`；
- `cutoff_len`、`max_samples`；
- `per_device_eval_batch_size`；
- `max_new_tokens/top_p/temperature`；
- `output_dir`。

WebUI 把配置写入输出目录后启动独立 CLI 子进程，环境包含：

```text
LLAMABOARD_ENABLED=1
LLAMABOARD_WORKDIR=<output_dir>
```

若含 DeepSpeed 配置还会设置 `FORCE_TORCHRUN=1`。`Runner.monitor()` 读取日志和状态；成功评测后从 `all_results.json` 生成展示文本。

### 3.2 SFT workflow 中的评测

`train/sft/workflow.py`：

- `predict_with_generate=True`：`ComputeSimilarity`，并设置 generation kwargs；
- 否则 `compute_accuracy=True`：`ComputeAccuracy` + `eval_logit_processor`；
- `do_eval`：`trainer.evaluate()`；
- `do_predict`：`trainer.predict()` 后 `save_predictions()`。

源码会警告批量 HF generate 很慢，建议大规模生成使用 `scripts/vllm_infer.py`。

生成预测通常落在 `generated_predictions.jsonl`，聚合指标在 `all_results.json`、`predict_results.json` 或 `eval_results.json`（具体由 Trainer 保存路径决定）。

## 4. NLG 后处理

`scripts/eval_bleu_rouge.py` 读取预测 JSONL，用 jieba 分词后计算：

- BLEU-4；
- ROUGE-1；
- ROUGE-2；
- ROUGE-L。

典型流程：

```bash
llamafactory-cli train examples/extras/nlg_eval/llama3_lora_predict.yaml
python scripts/eval_bleu_rouge.py saves/.../generated_predictions.jsonl
```

该脚本是离线后处理，不会加载模型。

## 5. 高吞吐推理脚本

`scripts/vllm_infer.py::vllm_infer()`：

- 复用 LLaMA-Factory 参数、template 与多模态处理；
- 用 vLLM 批量生成；
- 处理图像/视频等 multi-modal data；
- 输出预测文件。

它适合替代 `trainer.predict()` 的慢速逐批 generate，但要求 vLLM 支持当前模型和多模态输入。不要把它当作 OpenAI API server；服务入口仍是 `llamafactory-cli api`。

## 6. 统计工具

### 6.1 `stat_utils/cal_ppl.py`

`calculate_ppl()` 加载数据与模型，按 token 交叉熵计算 perplexity。其 `PairwiseDataCollatorWithPadding` 可处理成对数据。适合比较 checkpoint 的语言模型拟合程度，但 PPL 不代表指令遵循或偏好质量。

### 6.2 `length_cdf.py`

`length_cdf()` 统计 token 长度累计分布，用来选择 `cutoff_len`、估计截断比例。它应在大规模训练前运行，而不是训练后的质量评测。

### 6.3 `cal_flops.py`

`calculate_flops()` 根据模型结构和训练设置估算 FLOPs，用于理论计算量分析。

### 6.4 `cal_mfu.py`

- `compute_model_flops()`：估算模型每步计算量；
- `compute_device_flops()`：按设备/世界规模估算峰值；
- `calculate_mfu()`：由吞吐推导 Model FLOPs Utilization。

MFU 对模型结构、序列长度和硬件峰值假设敏感，应作为性能诊断，不是跨硬件绝对排名。

### 6.5 `cal_lr.py`

`calculate_lr()` 根据模型规模、batch/token 等启发式计算建议学习率，结果应视为初始搜索点。

## 7. Checkpoint 与格式转换

| 脚本 | 作用 |
|---|---|
| `hf2dcp.py` | Hugging Face checkpoint → PyTorch distributed checkpoint |
| `dcp2hf.py` | distributed checkpoint → Hugging Face 格式 |
| `megatron_merge.py` | MCA/Megatron checkpoint → HF |
| `qwen_omni_merge.py` | Qwen Omni 模型/LoRA 合并与完整保存 |
| `convert_ckpt/llamafy_qwen.py` | 旧 Qwen 权重重命名、分片与 config 转换 |
| `convert_ckpt/llamafy_baichuan2.py` | Baichuan2 → LLaMA-compatible 格式 |
| `convert_ckpt/tiny_qwen3.py` | 生成测试用 tiny Qwen3 |
| `convert_ckpt/tiny_llama4.py` | 生成测试用 tiny Llama4 |

`hf2dcp/dcp2hf` 与 v1 FSDP2/分布式 checkpoint 更相关；转换前必须保留正确 config。`megatron_merge.py` 对应 [13-分布式与硬件加速.md](./13-分布式与硬件加速.md) 的 MCA 路径。

## 8. Adapter/结构初始化脚本

### 8.1 PiSSA

`scripts/pissa_init.py::quantize_pissa()` 用于 PiSSA 初始化/量化准备。常规训练也可直接在 YAML 设置 `pissa_init`，详见 [16-高级算法与Extras.md](./16-高级算法与Extras.md)。

### 8.2 LoftQ

`scripts/loftq_init.py::quantize_loftq()` 创建 LoftQ 初始化 adapter，供低比特 LoRA 训练使用。

### 8.3 LLaMA Pro

`scripts/llama_pro.py::block_expansion()` 复制/扩展 transformer blocks，并通过 `change_name()` 改写权重键。后续训练用 `use_llama_pro` 只训练扩展层。该脚本改变模型结构，必须使用输出目录的新 config。

## 9. Benchmark 与 API 示例

- `scripts/bench_qwen.py`：构造 `DummyDataset` 与多模态 collator，测 Qwen 训练/前向性能；
- `scripts/api_example/test_toolcall.py`：调用 OpenAI-compatible API 演示工具调用；
- `scripts/api_example/test_image.py`：演示多模态图片请求。

API 示例默认假设服务已通过 `llamafactory-cli api ...` 启动，不是测试框架中的单元测试。

## 10. 如何选择评测路径

| 需求 | 路径 |
|---|---|
| 验证验证集 loss | `stage=sft, do_eval=true` |
| 生成回答并保存 | `do_predict=true, predict_with_generate=true` |
| 大规模高速生成 | `scripts/vllm_infer.py` |
| 中文生成 BLEU/ROUGE | predict 后运行 `eval_bleu_rouge.py` |
| 选择题 A/B/C/D 准确率 | legacy Evaluator（需直接 Python 调用，CLI 不支持） |
| 语言模型 PPL | `scripts/stat_utils/cal_ppl.py` |
| 训练性能 | FLOPs/MFU/length CDF 脚本 |

## 11. 当前版本修正

1. `llamafactory-cli eval` **不可用**；源码中的 `eval/` 仍在不等于命令仍受支持。
2. WebUI Evaluation 实际调用 `llamafactory-cli train` 和 SFT workflow，不调用 `Evaluator`。
3. WebUI 的“Predict”决定 `do_predict` 还是 `do_eval`，但两者都固定 `predict_with_generate=True`。
4. `eval_bleu_rouge.py` 是预测文件后处理，不是模型评测入口。
5. v1 当前没有独立 evaluation CLI；训练器主要实现训练和保存。
