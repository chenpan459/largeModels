# 06 — 数据模块源码分析

> 对应源码版本：LLaMA Factory `0.9.6.dev0`，默认 v0 数据栈 `src/llamafactory/data/`。

## 1. 完整数据通路

训练 workflow 调用：

```text
load_tokenizer()
get_template_and_fix_tokenizer()
get_dataset(template, model_args, data_args, training_args, stage, tokenizer, processor)
  → get_dataset_list()                 解析 dataset_info.json
  → _load_single_dataset()             从 Hub/文件/脚本/对象存储加载
  → align_dataset()                    converter 对齐统一 schema
  → merge_dataset()                    合并多个训练/验证集
  → split_dataset()                    生成 train/validation 字典
  → _get_dataset_processor()           按 stage 选择 tokenizer processor
  → Dataset.map(preprocess_dataset)    产生 token 级字段
  → get_dataset_module()               映射为 Trainer 参数
Trainer
  → stage 专用 DataCollator
  → padding、多模态张量、position IDs、4D mask
```

这条链分为三次 schema 变化：

1. 原始列：由用户数据决定；
2. 对齐列：固定为 `_prompt/_response/_system/_tools/_images/_videos/_audios`；
3. tokenized 列：由 stage processor 决定。

## 2. `dataset_info.json` 与 `DatasetAttr`

`parser.py::get_dataset_list(dataset_names, dataset_dir)` 支持三种配置源：

- `dataset_dir` 是字典：直接作为 dataset info；
- `"ONLINE"`：数据集名直接作为当前 Hub 的 repo id；
- `"REMOTE:<repo>"`：从 Hugging Face dataset repo 下载 `dataset_info.json`；
- 其他字符串：读取 `<dataset_dir>/dataset_info.json`。

每个名称被解析为 `DatasetAttr`。数据来源优先级为：

1. `hf_hub_url/ms_hub_url/om_hub_url`；
2. `script_url`；
3. `cloud_file_name`；
4. `file_name`。

Hub 选择受 `USE_MODELSCOPE_HUB`、`USE_OPENMIND_HUB` 影响。`cloud_file_name` 不是普通 HTTP URL：实现使用 `fsspec`，仅接受 `s3://`、`gs://`、`gcs://`，并只读取 JSON/JSONL。

`DatasetAttr` 的关键字段：

- 基础：`formatting`（`alpaca/sharegpt/openai`）、`ranking`、`subset`、`split`、`folder`、`num_samples`；
- 通用列：`system/tools/images/videos/audios`；
- 偏好列：`chosen/rejected/kto_tag`；
- Alpaca：`prompt/query/response/history`；
- ShareGPT/OpenAI：`messages`；
- 标签映射：`role_tag/content_tag/user_tag/assistant_tag/observation_tag/function_tag/system_tag`。

## 3. `_load_single_dataset()`：实际加载行为

来源到加载器的映射：

- `hf_hub`、`script`、本地 `file`：Hugging Face `datasets.load_dataset()`；
- `ms_hub`：`modelscope.MsDataset.load()` 后转 HF Dataset；
- `om_hub`：`openmind.OmDataset.load_dataset()`；
- `cloud_file`：`read_cloud_json()` 后 `Dataset.from_list()`。

本地文件可传文件或目录；目录内文件必须全部是同一种受支持格式，格式由 `FILEEXT2TYPE` 决定。流式本地文件先正常加载，再按 `dataloader_num_workers` 转为 iterable shards；其他来源直接把 `streaming=True` 传给加载器。

采样顺序是先 `num_samples`，再 `max_samples`。`num_samples` 大于数据集长度时会有放回补采样，保证结果数量精确；此逻辑不支持 streaming。

加载完成后立即调用 `align_dataset()`，所以 merge 发生在统一 schema 之后。

## 4. Converter：原始格式到统一 schema

`converter.py` 维护可扩展注册表：

```text
DATASET_CONVERTERS = {
  "alpaca": AlpacaDatasetConverter,
  "sharegpt": SharegptDatasetConverter,
  "openai": OpenAIDatasetConverter,
}
```

可通过 `register_dataset_converter(name, class)` 增加格式。`align_dataset()` 对每条数据执行 converter，并移除全部原始列。

统一输出精确为：

```text
_prompt   : 奇数条消息，通常为 user/assistant/.../user
_response : 普通任务 1 条；pairwise 2 条；KTO 用空响应的位置编码好/坏
_system   : 字符串
_tools    : 字符串（OpenAI converter 可把 dict/list JSON 序列化）
_images   : list 或 None
_videos   : list 或 None
_audios   : list 或 None
```

### Alpaca converter

`history` 被展开为 user/assistant 对；当前 `prompt` 与 `query` 用换行拼成最后一条 user。普通响应产生一条 assistant；ranking 数据产生 chosen、rejected 两条；KTO 根据布尔 `kto_tag` 把真实响应放在两个位置之一。

### ShareGPT converter

第一条 system 可从 messages 中剥离。其余角色必须严格交替：

- 奇数位：user 或 observation；
- 偶数位：assistant 或 function。

非 ranking 数据对齐后的消息数必须为偶数；ranking prompt 必须为奇数，并从独立 `chosen/rejected` 字典读取两个答案。异常样本不会立刻从 Dataset 删除，而是转换为空 prompt/response，随后由 processor 丢弃。

### OpenAI converter

它处理 `tool_calls`，把 assistant 工具调用转为内部 `function`；连续 tool 结果会合并为一条 `observation`。此版本还会在没有 tools 时注入或追加 `"detailed thinking off"` system 文本，这是 OpenAI converter 特有行为，迁移数据时不能忽略。

本地媒体路径由 `_find_medias()` 尝试拼到 `data_args.media_dir`；文件不存在时保留原始值并警告。

## 5. 合并、切分与分布式同步

`merge_dataset()` 支持：

- `concat`；
- `interleave_under` → `first_exhausted`；
- `interleave_over` → `all_exhausted`；
- `interleave_once` → `all_exhausted_without_replacement`。

显式 `eval_dataset` 与 `val_size > 0` 互斥。非流式数据用 `train_test_split()`；流式数据先 buffer shuffle，再用 `take/skip` 划分，故 `val_size` 在 streaming 下按整数样本数解释。

`eval_on_each_dataset=True` 时，各验证集不合并，最终键先命名为 `validation_{dataset_name}`，再由 `get_dataset_module()` 转为 `eval_dataset: {dataset_name: Dataset}`。

加载与预处理分别位于 `training_args.main_process_first()`：

- `data_shared_file_system=False`：每台机器的 local main process 先做；
- `True`：全局主进程先做，适合所有节点共享缓存目录。

非主进程 `Dataset.map()` 的 `load_from_cache_file` 会被强制开启，减少重复处理。

## 6. Processor 分派

`_get_dataset_processor()` 的精确分派：

| 传入 stage/条件 | Processor |
|---|---|
| `pt` | `PretrainDatasetProcessor` |
| `sft` 且非生成 | `SupervisedDatasetProcessor` |
| `sft + packing` | `PackedSupervisedDatasetProcessor` |
| `rm` | `PairwiseDatasetProcessor` |
| `kto` | `FeedbackDatasetProcessor` |
| 其余（包括 `ppo`，以及 SFT 生成式 eval） | `UnsupervisedDatasetProcessor` |

DPO workflow 传入的是 `stage="rm"`，所以复用 pairwise processor。数据层的 stage Literal 没有 `dpo`。

`_get_preprocessed_dataset()` 通过 batched `Dataset.map()` 调用 processor，移除 converter 列。若当前进程应记录日志，会打印首条 tokenized 样本；空 PT 数据报“样本不足”，其他 stage 报“没有合法样本”。

## 7. 各 Processor 的精确输出键

普通 SFT 与 PPO/生成式评估：

```text
input_ids, attention_mask, labels, images, videos, audios
```

Packed SFT：

```text
input_ids, attention_mask, position_ids, labels,
images, videos, audios,
packing_params（仅 neat_packing）
```

Pairwise（RM/DPO）：

```text
chosen_input_ids, chosen_attention_mask, chosen_labels,
rejected_input_ids, rejected_attention_mask, rejected_labels,
images, videos, audios
```

KTO：

```text
input_ids, attention_mask, labels,
kl_input_ids, kl_attention_mask, kl_labels,
kto_tags, images, videos, audios
```

PT 最终提供 CLM 所需 token 列，由 `DataCollatorForLanguageModeling` 生成 labels。

SFT 编码先调用多模态 plugin，再调用 `template.encode_multiturn()`。默认 prompt label 为 `IGNORE_INDEX=-100`；`train_on_prompt=True` 才训练输入。`mask_history=True` 时反转各轮以优先保留最后一轮，并只训练最后回答。`efficient_eos` 会显式补 EOS。

Packed SFT 用 greedy knapsack 装入 `cutoff_len`。`neat_packing` 的 attention mask 不是二值：第 1、2、3 个子序列分别写 1、2、3，用于阻断跨样本注意力；同时保存各子序列边界及媒体归属。

## 8. `DatasetModule` 的精确契约

`data_utils.py` 中定义的是：

```text
DatasetModule(TypedDict)
  train_dataset: Dataset | IterableDataset | None
  eval_dataset : Dataset | IterableDataset | dict[str, Dataset] | None
```

实际返回字典只写存在的键，因此消费者应使用 `.get()` 或确认配置。没有 `predict_dataset`；各 workflow 的预测直接使用 `dataset_module["eval_dataset"]`。

如果 `tokenized_path` 已存在，`get_dataset()` 直接 `load_from_disk()` 并忽略其他数据参数；streaming 时仅把 train 转 iterable。若路径尚不存在，则完成全部 tokenization 后仅由 `training_args.should_save` 的进程保存 DatasetDict；保存 tokenized 数据时禁止 streaming。

## 9. Template、tokenizer 与多模态 plugin

`template.py` 的 `TEMPLATES` 是运行时注册表，`register_template()` 定义 user/assistant/system/function/observation/tools/prefix formatter、stop words、thinking 行为及 `mm_plugin`。

`get_template_and_fix_tokenizer()`：

1. 使用显式 `data_args.template`；
2. 未指定时尝试解析 `tokenizer.chat_template`；
3. 都没有则用 `empty`；
4. 应用 `tool_format/default_system/enable_thinking/preserve_thinking`；
5. `fix_special_tokens()` 修复 EOS/PAD并注册 stop words；
6. `fix_jinja_template()` 在必要时写 tokenizer chat template。

`train_on_prompt` 与 `efficient_eos` 不兼容。模板对象来自全局注册表，函数会原地修改 formatter/default system/reasoning flags；同一进程创建多套不同配置时要警惕状态串扰。

多模态 plugin 有三层接口：

- `process_messages()`：tokenization 前把 `<image>/<video>/<audio>` 展开为模型格式；
- `process_token_ids()`：tokenization 后插入或调整媒体 token；
- `get_mm_inputs()`：batch 阶段调用 processor，返回 pixel values、audio features、grid、cross-attention mask 等模型参数。

## 10. Collator

`MultiModalDataCollatorForSeq2Seq` 先从样本弹出媒体字段，调用 plugin 生成多模态张量，再交给 Transformers `DataCollatorForSeq2Seq` padding。它还处理：

- 多模态 RoPE 的 `position_ids/rope_deltas`；
- packing 后逐子序列计算 mRoPE；
- 没有媒体的 ZeRO-3/FSDP batch 注入 dummy image/audio，避免各 rank 图结构不一致导致 hang；
- MiniCPM、Mllama、Qwen Omni 等模型专用输入结构。

`SFTDataCollatorWith4DAttentionMask` 在 `block_diag_attn=True` 且非 FA2 时把带子序列编号的 2D mask 扩展为 4D causal block mask。`neat_packing + flash_attention_2` 要求 batch size 为 1，去除 padding 后把 attention mask 设为 `None`，交给 Transformers 的 packed causal 路径。

`PairwiseDataCollatorWithPadding` 把 batch 展开为前 N 条 chosen、后 N 条 rejected。`KTODataCollatorWithPadding` 分别 collate target 与 KL 样本，再写回 `kl_*` 和 `kto_tags`。

## 11. 扩展点与陷阱

- 新原始格式：实现 `DatasetConverter` 并调用 `register_dataset_converter()`。
- 新 stage：实现 `DatasetProcessor`，修改 `_get_dataset_processor()`，并提供匹配的 collator。
- 新模板：调用 `register_template()`；模型专用多模态协议应同时实现 plugin。
- 自定义媒体：必须同时考虑 converter 路径解析、processor 样本字段和 collator batch 张量。

常见错误：

1. 把 `cloud_file_name` 当 HTTP URL；当前只支持 S3/GCS。
2. DPO 数据忘记 `ranking: true`，或错误寻找 DPO processor。
3. ShareGPT 角色/消息数不满足严格交替，样本会在后续静默丢弃并打印 warning。
4. 显式 eval dataset 与 `val_size` 同时配置。
5. `predict_with_generate` 会让 SFT eval 改用 unsupervised processor，labels 表示待生成答案，不再走普通 SFT mask。
6. 多模态占位符数量必须与媒体数量匹配；processor 不是可选装饰，VLM 没有正确 `AutoProcessor` 会在 plugin 校验时报错。
7. packing、neat packing、attention backend 和模型 mRoPE 支持存在组合约束；Omni 目前不支持 packed sequence。
