# 12 — 对齐与偏好训练

本文基于 LLaMA-Factory `0.9.6.dev0` 的 v0 默认架构，分析 RM、PPO、DPO、KTO 的真实数据流、模型角色和损失实现。v1 目前只实现 SFT、RM、DPO，见 [14-v1实验架构.md](./14-v1实验架构.md)。

## 1. 总入口与阶段路由

统一入口是 `src/llamafactory/train/tuner.py`：

```text
llamafactory-cli train config.yaml
  → cli.main()
  → launcher.launch()
  → train.tuner.run_exp()
  → get_train_args()
  → _training_function()
  → run_rm / run_ppo / run_dpo / run_kto
```

`FinetuningArguments.stage` 的合法值定义在 `src/llamafactory/hparams/finetuning_args.py`，包括 `pt/sft/rm/ppo/dpo/kto`。四种对齐阶段的公共结构是：

```text
workflow.py：加载 tokenizer/template/dataset/model，创建 collator/trainer
trainer.py ：定义损失、forward、指标和保存行为
```

核心数据组件：

| 阶段 | 数据处理器 | Collator | Trainer |
|---|---|---|---|
| RM、DPO | `data/processor/pairwise.py` | `PairwiseDataCollatorWithPadding` | `PairwiseTrainer` / `CustomDPOTrainer` |
| PPO | `data/processor/unsupervised.py` | `DataCollatorWithPadding` | `CustomPPOTrainer` |
| KTO | `data/processor/feedback.py` | `KTODataCollatorWithPadding` | `CustomKTOTrainer` |

## 2. RM：训练奖励模型

### 2.1 调用链

```text
train/tuner.py::_training_function
  → train/rm/workflow.py::run_rm
  → get_dataset(..., stage="rm")
  → load_model(..., add_valuehead=True)
  → PairwiseDataCollatorWithPadding
  → train/rm/trainer.py::PairwiseTrainer.train
  → PairwiseTrainer.compute_loss
```

`run_rm()` 为因果语言模型附加 TRL `AutoModelForCausalLMWithValueHead` 的 value head。模型输出的第三项 `values` 是每个 token 的标量奖励。

### 2.2 配对损失

Collator 将 batch 排成前半 chosen、后半 rejected。`PairwiseTrainer.compute_loss()`：

1. 用 `attention_mask.sum()-1` 找每条序列最后一个有效 token；
2. 取该位置 value head 分数 `r_chosen`、`r_rejected`；
3. 计算 Bradley–Terry 风格损失：

```text
L_RM = -mean(log sigmoid(r_chosen - r_rejected))
```

预测结果由 `save_predictions()` 写入 `generated_predictions.jsonl`，每行是 chosen/rejected 分数。模型保存时 `FixValueHeadModelCallback` 修正 value-head 权重命名；导出阶段 `train/tuner.py::export_model()` 还会复制 `value_head.safetensors` 或旧格式文件。

示例：`examples/train_lora/qwen3_lora_reward.yaml`。

## 3. PPO：策略、参考模型与奖励模型

### 3.1 三类模型

PPO 同时涉及：

- **策略模型**：待优化，带 value head；
- **参考模型**：用于 KL 约束；LoRA 时可通过禁用当前 adapter 复用底座；
- **奖励模型**：输出生成回答的标量奖励。

调用链：

```text
train/ppo/workflow.py::run_ppo
  → load_model(..., add_valuehead=True)
  → trainer_utils.create_ref_model(..., add_valuehead=True)
  → trainer_utils.create_reward_model(...)
  → CustomPPOTrainer(...)
  → CustomPPOTrainer.ppo_train()
     → get_inputs()       # 策略模型 generate
     → get_rewards()      # 奖励模型/API 打分
     → PPOTrainer.step()  # policy/value/KL 更新
```

### 3.2 奖励模型的三种装载方式

`create_reward_model()` 根据 `reward_model_type` 分支：

| 类型 | 行为 |
|---|---|
| `lora` | 把 RM adapter 以 `reward` 名装到策略底座，推理时 `replace_model()` 在 `default/reward` adapter 与 value head 间切换 |
| `full` | 独立加载完整 RM，并由 Accelerate/DeepSpeed 放置 |
| `api` | `reward_model` 是 HTTP URL，`ppo_utils.get_rewards_from_server()` 请求远程打分 |

关键限制在 `FinetuningArguments.__post_init__()`：PPO 必须提供 `reward_model`；LoRA 型 RM 要求策略也用 LoRA。完整 RM 必须与策略模型共享 tokenizer 和词表。

### 3.3 自定义循环

`CustomPPOTrainer.ppo_train()` 没有直接使用 HF `Trainer.train()`：

1. 从 dataloader 取 prompt；
2. 按 mini-batch 生成 response；
3. 计算 reward；
4. 调 TRL 0.8.x 的 `step(queries, responses, rewards)`；
5. 记录 `ppo/loss/total`、平均 reward、学习率；
6. 按 `save_steps` 保存。

当前源码显式要求 `trl>=0.8.6,<=0.9.6`，并且 PPO 不支持 eval dataset，也不支持 `resume_from_checkpoint`。这些是运行前必须确认的版本级限制。

重要参数来源：`hparams/finetuning_args.py::RLHFArguments`：

- `ppo_buffer_size=1`
- `ppo_epochs=4`
- `ppo_target=6.0`
- `ppo_score_norm=False`
- `ppo_whiten_rewards=False`

## 4. DPO：成对偏好直接优化

### 4.1 调用链

```text
train/dpo/workflow.py::run_dpo
  → get_dataset(..., stage="rm")  # 注意：配对数据沿用 rm processor
  → load_model(policy)
  → create_ref_model()
  → PairwiseDataCollatorWithPadding
  → CustomDPOTrainer
  → get_batch_loss_metrics()
     → concatenated_forward(policy)
     → compute_reference_log_probs()
     → compute_preference_loss()
```

`concatenated_forward()` 一次 forward 同时处理 chosen/rejected，避免两次前向。`get_batch_logps()` 聚合 answer token 的 log probability。

### 4.2 参考模型策略

`trainer_utils.create_ref_model()`：

- 显式 `ref_model`：独立加载；
- LoRA 且未指定：返回 `None`，计算参考概率时临时 `disable_adapter()`；
- full/freeze 且未指定：重新加载同一底座作为冻结参考模型；
- ORPO/SimPO：`use_ref_model=False`，不创建参考模型。

DeepSpeed 和 FSDP 下，`CustomDPOTrainer.__init__()` 分别调用 TRL `prepare_deepspeed()`、`prepare_fsdp()`；FSDP2 使用 Accelerate 的 `fsdp2_prepare_model()`。

## 5. `pref_loss` 各变体

配置定义：

```text
src/llamafactory/hparams/finetuning_args.py::RLHFArguments.pref_loss
sigmoid | hinge | ipo | kto_pair | orpo | simpo
```

实现分成两层：

- `sigmoid/hinge/ipo/kto_pair`：进入 TRL `DPOTrainer.dpo_loss()`；
- `orpo/simpo`：由 `CustomDPOTrainer` 本地实现，且不使用参考模型。

令 `Δπ = log π(y+|x)-log π(y-|x)`，`Δref` 同理：

| `pref_loss` | 核心含义 | 源码行为 |
|---|---|---|
| `sigmoid` | 标准 DPO：`-logσ(β(Δπ-Δref))` | 支持 `dpo_label_smoothing`，即 cDPO |
| `hinge` | margin hinge | 由 TRL `dpo_loss()` 实现 |
| `ipo` | IPO 二次目标 | 使用每 token 平均 logp，避免长度主导 |
| `kto_pair` | 成对 KTO 风格损失 | 仍属于 DPO 配对训练，不等于独立 `stage=kto` |
| `orpo` | SFT NLL + β×odds-ratio loss | 无 reference；`odds_ratio_loss()` 本地实现 |
| `simpo` | reference-free，带目标 margin γ | 无 reference；`simpo_loss()` 本地实现 |

ORPO：

```text
log_odds = (logp+ - logp-) - (log(1-exp(logp+)) - log(1-exp(logp-)))
L = -logp+ - β logσ(log_odds)
```

SimPO：

```text
L = -logσ(β(average_logp+ - average_logp-) - γ)
```

其中源码写成 `gamma_logratios=simpo_gamma/beta` 后再乘 beta。IPO、ORPO、SimPO 都在 `concatenated_forward()` 中使用平均 logp；其他损失使用总 logp。

扩展项：

- `pref_ftx`：额外加入 chosen response 的 SFT loss；
- `pref_bco_weight`：将 BCO loss 与偏好 loss 加权，基线由 TRL `RunningMoments` 维护；
- `ld_alpha`：传给 `get_batch_logps()`，实现 LD-DPO 对冗长 token 的重权；
- `pref_beta`：偏好温度/正则强度；
- `dpo_label_smoothing`：只允许 `sigmoid`，否则参数校验报错；
- `simpo_gamma`：SimPO 目标奖励间隔。

## 6. KTO：非配对二元反馈

KTO 的样本只需“该回答可取/不可取”标签，不要求同一 prompt 下成对出现。

```text
data/converter.py
  → 标准化 kto_tag
data/processor/feedback.py::FeedbackDatasetProcessor
  → input_ids/labels
  → kl_input_ids/kl_labels
  → kto_tags
data/collator.py::KTODataCollatorWithPadding
  → CustomKTOTrainer.get_batch_loss_metrics()
```

`FeedbackDatasetProcessor` 会构造目标样本和用于 KL 估计的错位样本。`CustomKTOTrainer`：

1. `forward(prefix="")` 计算目标 logp；
2. `forward(prefix="kl_")` 计算 KL 样本 logp；
3. 以布尔 `kto_tags` 切出 desirable/undesirable；
4. 用策略与参考模型 logp 调 TRL `kto_loss()`；
5. 可按 `kto_chosen_weight`、`kto_rejected_weight` 调节类别权重；
6. 可通过 `pref_ftx` 对 desirable 样本附加 SFT loss。

KTO 默认使用参考模型；LoRA 时同样通过禁用 adapter 得到 reference。示例：`examples/train_lora/qwen3_lora_kto.yaml`。

## 7. 选择建议与边界

| 条件 | 推荐阶段 |
|---|---|
| 有同 prompt 的 chosen/rejected | DPO；若要训练后续 PPO 的评分器则 RM |
| 只有独立好/坏反馈 | KTO |
| 有可靠 RM，且需要在线采样优化 | PPO |
| 希望省掉参考模型显存 | ORPO 或 SimPO |
| 标签可能有噪声 | sigmoid + 适量 `dpo_label_smoothing` |

不要混淆：

1. `stage=kto` 是非配对反馈流程；`pref_loss=kto_pair` 是 DPO 配对损失。
2. DPO workflow 传 `stage="rm"` 给数据层是当前实现的复用设计，不表示它在训练 RM。
3. PPO 是绑定旧 TRL API 的兼容实现，不是当前 TRL 新版 PPOTrainer 的直接封装。
4. v1 DPO 目前只接受 `sigmoid/orpo/simpo`；v0 的六种 `pref_loss` 不能原样迁移。
